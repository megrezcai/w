# 章节与谈判规则

每名角色有利益权重、信任（0～1）、被同伙背弃的确信度、证据、承诺和已经承认的秘密。这是可调整的博弈近似，不是对真实人类心理的预测。

## 每轮处理

1. 本地模型解析交际行为、话题和明确提出的承诺，不读取未披露秘密原文。
2. 程序核对游戏提供的证据库存与承诺权限。口头说法不变成实证。
3. 游戏证据可以更新角色对被出卖的确信；每份证据只算一次。
4. 程序评估利益、披露成本、底线、依赖与必要条件，选择策略。
5. 自然模式下模型生成短回应，程序追加审定的案件陈述或交换条件；严格模式直接采用作者台词。
6. 原子保存新状态与笔录。历史保存在 SQLite，模型仅接收最近8条消息，事实和承诺另外持久保存。当前未做长对话自由文本记忆摘要，因此早期闲聊细节可能遗忘。

## 当前版本公式

- 未兑现承诺的可信度 = `0.35 + 0.65 × trust`；兑现后为1；违背后不再计收益。
- 每项利益合计值限定在 -1～1，乘该利益权重后求和得到 `benefit`。
- 相关实证筹码限定在0～6。
- 合作收益 = `benefit + 0.65 × leverage + 0.4 × trust`。
- 披露成本 = `secret.cost × (1 - 0.45 × betrayal)`。
- 收益达到成本，且秘密依赖、必需承诺、至少一项相关证据满足时，披露当前话题的一条秘密。
- 没有相关证据要求时 `evidence=[]`；无必要承诺时 `requires_offers=[]`；二者并非所有情报都强制要求。
- 底线命中时拒绝本轮整组交易，不因为收益高就接受。
- 示好首次增加0.08信任，威胁首次降低0.15，后续同种话术不累计。兑现/违约每个承诺分别只计一次。

这些数值集中在 `caseforge/engine.py`，供游戏设计调参。秘密的 truth、cost、前置条件都由程序掌握，模型不直接批准披露。不支持任意程序条件、真正的未来行动规划或完整经济模拟。

## 章节字段

- `public_brief`：玩家已知的开场信息。
- `characters[].persona`：可发给模型的人设；避免包含隐藏案情。
- `public_knowledge`：角色可自由谈及的内容。
- `interests`：利益 ID、标签、权重（0～10）。
- `red_lines`：不可接受的 offer ID。
- `secrets`：话题、匹配提示、truth、denial、cost、requires、evidence、requires_offers。
- `evidence[].effects`：对应角色、证据筹码、背弃确信度。这个描述在玩家库存里可见。
- `offers[].benefits`：对应角色、利益 ID、变化值（-1～1）。
- `counter_line`：角色提出此条件时的审定台词。

JSON Schema 校验后还检查 ID 唯一性、所有交叉引用、秘密依赖无环及数值有限。不负责自动判定剧情是否合理或秘密是否可达，作者要试玩验证。

## 资料隔离的边界

剧本整理器需要读取全章，它是作者工具。运行时语义解析器只获得话题、提示和可用条件；演员只获得公开人设、公开知识、策略与最近已说出的对话，未获得新秘密真相。秘密陈述直接由引擎追加。

这减少提前泄密，不能证明自然模式绝不猜中秘密或产生误导内容。人设、话题标签、玩家引用、先前对话都可能间接泄露信息，作者需要审查。严格台词模式可以禁止未经作者审定的新台词。语义解析的承诺识别仍有误判可能；对关键交易，游戏应采用显式确认 UI 和受信任的 offer_ids，并按需关闭自动语义承诺识别。
